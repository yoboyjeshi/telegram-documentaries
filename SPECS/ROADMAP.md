# ROADMAP — Build order (one SDD loop per feature)

Build in order. Each feature is one SDD loop: spec, Build orchestrator, review, manual phone test, merge PR. Start a fresh OpenCode session per feature to conserve tokens.

1. Telegram Gateway: connect via long polling using TELEGRAM_BOT_TOKEN from .env; implement /start and /restart (greet plus reset); echo text replies to confirm the pipe on the phone; establish per-chat session store and state-machine scaffold. Done when the bot replies on the phone and /restart resets to GREETING. **Status: implemented and merged** (2026-10-11, PR #1, squash `4bb03ab`).
2. The Bouncer: on photo upload, download to a chat-namespaced temp path; Bouncer agent confirms a human face; human advances to INTERVIEW, non-human gets a humorous refusal and stays in AWAITING_PHOTO. Done when a selfie advances and an object/pet photo is rejected without crashing. **Status: implemented; automated verification complete and manual phone test passed** (2026-10-11, branch `feature/2026-10-11-bouncer`; post-verification fixes `192e8d7`, `82afd69`; PR #2 merged 2026-10-17).
3. The Interviewer (+ orchestrator): 5 to 7 pointed questions one at a time; maintain state; collect answers into a trait summary; this agent orchestrates remaining stages. Done when the bot interviews and produces a trait summary. **Status: implemented and merged (PR #3)** (2026-10-17, branch `feature/2026-10-17-interviewer`; 6 questions via `app/interviewer.py` + `app/orchestrator.py`; commits `27c0cf5` implement, `14f35f7` review fixes, `e36e963` polish; manual phone-test result not recorded in committed checklist). Accuracy note on the original wording "this agent orchestrates remaining stages": in the shipped code the ADK Interviewer agent only asks questions and summarises; `app/orchestrator.py` and `app/bot.py` own progression and task ownership.
4. The Converter: pass original portrait plus interview summary to flash-image; generate hybrid-animal avatar; send image to chat. Done when a generated animal-hybrid image arrives after the interview. **Status: implemented, phone tested and merged (PR #4, squash `3dc2ad4`); 224 offline tests, ruff and mypy pass after merge.**
5. The Scripter: flash-lite British documentary-narrator persona; ONE dramatic paragraph, max about 90 words, plain text only. Done when a single narration paragraph is produced from the traits. **Status: implemented, phone tested and merged (PR #5, squash `0dec595`); 439 offline tests, ruff and mypy passed.**
6. The Narrator: send the Scripter paragraph through flash-tts-preview; save audio to a chat-namespaced temp path; send as a Telegram voice/audio message; mark DONE. Done when a voiceover plays back in the chat. **Status: implemented, phone tested and merged.** Accepted at `397bf94` on `feature/2026-10-18-narrator` (native Codio Python 3.11.2: 795 tests passed, Ruff and mypy clean on 21 files; user confirmed full voice playback, two runs in one process, terminal `DONE` and both resets during narration). The user merged PR #6 as `b2d8803`, whose `main` tree matches the accepted `397bf94` content. This evidence is historical and covers Feature 6 only.
7. Resilience and reset hardening (plus submission documentation): /start and /restart fully reset from EVERY stage; try/except on every Telegram and Gemini call with notify plus retry; handle edge cases (photo during interview, text during Bouncer, API timeout, unsupported uploads); temp-media hygiene; accurate architecture docs and diagrams. Done when a TA-style stress test passes with no reboot. **Status: IN PROGRESS on `feature/2026-10-18-submission-readiness`; NOT accepted.** Specs: `SPECS/2026-10-18-submission-readiness/` (requirements, architecture, plan, validation, summary-review). Verified baseline only: unmodified `b2d8803` ran 795 tests passed in 8.53s with Ruff and mypy clean on 21 files (Windows Python 3.13.12, real FFmpeg, external network blocked). Final local readiness gate: 906 passed in 10.88s, Ruff clean, mypy22 clean (same local environment), after review corrections. Independent source review closed with no remaining defects found; native Codio Python 3.11 gate, phone stress checklist and user merge remain pending; five baseline privacy tests are approved for leakage-assertion changes (the consolidated 1072-assertion sweep found no others of that class), plus two approved integration fixture/synchronisation adaptations that preserve every assertion in those tests.
8. End-to-end verification and submit: run the full pipeline twice in a row on the phone, same process, no restart; confirm .env never committed and repo is public; merge final PR; submit the public repo.

Keep each PR focused on one feature. If logic drifts, update the specs rather than patch snippets.

Four roles are ADK agents (Bouncer, Interviewer, Converter, Scripter); the Narrator is a direct `google-genai` TTS integration, not an ADK agent. ADK runs the model calls only: plain application code owns the stage machine, interview history, deadlines and task ownership, and there is no ADK parent agent. The assistant never merges a PR or enables auto-merge.
